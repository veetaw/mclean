# App

Xcode project generated by `xcodegen` (2.46.0) from `project.yml`, per the
`Agent:MainAppUI` phase (Phase 2) — see `ARCHITECTURE.md`. The generated
`MCleanPro.xcodeproj` is gitignored (fully reproducible); regenerate it
with:

```sh
cd App && xcodegen generate
```

Both targets build the same shared SwiftUI code from
`Packages/MainAppUI` — neither target directory contains real UI code, only
a minimal `@main App` entry point, an `Info.plist`, and an `.entitlements`
file.

- `AppStoreTarget/` — `MCleanPro-AppStore`: sandboxed
  (`com.apple.security.app-sandbox`), compiled with
  `SWIFT_ACTIVE_COMPILATION_CONDITIONS: APPSTORE` (the single place
  `BuildFlavor.current` reads that flag — see
  `Packages/MainAppUI/Sources/MainAppUI/Capabilities/`), bundle id
  `com.mcleanpro.app.appstore`. No `RemoteControlServer`/privileged-helper
  entitlements — gated centrally via the runtime `Capabilities` registry,
  not scattered `#if APPSTORE` checks.
- `DeveloperIDTarget/` — `MCleanPro-DeveloperID`: not sandboxed, hardened
  runtime enabled ahead of a future real notarization pass, bundle id
  `com.mcleanpro.app` (matching the `com.mcleanpro` prefix used by
  `PrivilegedHelperXPC.PrivilegedHelperConstants.machServiceName`). Full
  feature set: `RemoteControlServer` LAN listener + Bonjour, privileged
  helper (once `PrivilegedHelper/` is scaffolded), unrestricted filesystem
  scanning.

Local builds skip codesigning entirely (`CODE_SIGN_IDENTITY: "-"`,
`CODE_SIGNING_REQUIRED/ALLOWED: NO`) so `xcodebuild build` succeeds without
a real Apple Developer Team ID. This is a **local dev convenience only** —
real notarization/distribution signing is `Scripts/` + a later phase, not
configured here.

```sh
cd App
xcodegen generate
xcodebuild -project MCleanPro.xcodeproj -scheme MCleanPro-DeveloperID -configuration Debug build
xcodebuild -project MCleanPro.xcodeproj -scheme MCleanPro-AppStore -configuration Debug build
```
